# 在活着的系统上排障与改动

这份 skill 来自一个真实项目：把 WorldBox 的存档接给多个扮演国家领袖的 LLM agent。

我在那个项目里**把用户正在玩的游戏弄到存不了档**，也用错误的测量得出过"发现 bug"的结论。
下面每一条都是踩出来的，不是推演出来的。

**适用范围**：任何"程序正被使用、而你只能从外部读它/改它"的场合——
游戏存档、本地数据库、桌面软件的缓存、正在被别的进程占用的日志。

---

## 一、第一原则：只读也会弄坏对方

"我只是读一下"不成立。Windows 上**打开一个文件的共享模式决定了别人能不能写、能不能删**。

### 真实案例（值得完整记住）

某游戏存档的第一步是删除旧的统计库再重写：

```
DBManager.saveToPath(pPath):
    File.Delete(pPath)        ← 先删
    ...复制新的进去
```

而 SQLite 打开文件时**不共享"删除"权限**。于是——

> 只要我的工具还开着那个 `map_stats.s3db`，游戏这次存档就**必然失败**，
> 用户看到的是"工具读取存档后，下一次存档就存不进去了"。

游戏自己的日志给出了铁证（**去读对方的日志，它比你的推理可靠**）：

```
Error during saving
System.IO.IOException: The process cannot access the file
'...\WorldBox\saves\save3\map_stats.s3db' because it is being used by another process.
  at System.IO.FileSystem.DeleteFile ...        ← 注意失败点是 Delete
  at db.DBManager.saveToPath ...
```

### 做法：读副本，不读原件

```python
def open_elsewhere(path: Path) -> Path:
    """把对方的文件复制成自己的临时副本，返回副本路径。之后只碰副本。"""
    fd, name = tempfile.mkstemp(prefix="mirror-", suffix=path.suffix,
                                dir=tempfile.gettempdir())
    with os.fdopen(fd, "wb") as out, open(path, "rb") as src:
        shutil.copyfileobj(src, out, 1024 * 256)
    return Path(name)
```

- 复制失败就重试几次（对方可能正在写），并用"能不能正常解析"来验证这次复制是否完整。
- 复制到**自己的**目录；临时目录不可用时才退回直接打开，**并在状态里如实说明代价**，
  不要静默降级（静默降级 = 用户永远不知道自己在冒什么风险）。
- 副本用完删掉。

### 同一条原则的其它形态

| 你的动作 | 可能的干扰 | 更安全的做法 |
|---|---|---|
| 长期持有对方文件的句柄 | 对方无法删除/替换（如上） | 读副本；或读完立刻关闭 |
| 往对方目录里写状态/缓存文件 | 污染对方的数据目录、被对方当输入 | 优先写自己的目录；必须写对方目录时用"临时文件 + 原子替换" |
| 改对方文件的 mtime | 对方的增量同步/清理逻辑误判 | 不要 touch；需要判断新旧就记录在别处 |
| 在对方目录留 `.tmp-*` | 被对方扫描/上传 | 临时文件放在自己目录 |
| 依赖"对方写入是原子的" | 读到半个文件 | 复制后校验；解析失败就重试整个读取 |

## 二、定位责任方：用非破坏性的探针，不要靠猜

### 我犯过的错：无效实验

我一开始用"以独占方式打开文件"（`FileShare.None`）来判断"是不是被占用了"，
结果**所有文件都报"被占用"**——因为对方程序自己也开着它们。这个实验**无法区分责任方**，
只会让你把责任推给错误的对象。

**判据要针对"对方到底要做什么"**：这个案例里对方要的是**删除**，所以判据是
"我能不能拿到 DELETE 权限"（删除会检查所有已存在句柄是否共享了删除）。

### 探针：申请 DELETE 权限，但**不真删**

```powershell
Add-Type -Namespace P -Name N -MemberDefinition @'
[System.Runtime.InteropServices.DllImport("kernel32.dll", SetLastError=true, CharSet=System.Runtime.InteropServices.CharSet.Unicode)]
public static extern System.IntPtr CreateFileW(string n, uint a, uint s, System.IntPtr sec, uint d, uint f, System.IntPtr t);
[System.Runtime.InteropServices.DllImport("kernel32.dll", SetLastError=true)]
public static extern bool CloseHandle(System.IntPtr h);
'@
$INVALID=[System.IntPtr](-1)
# 0x00010000 = DELETE 权限；share=7 = READ|WRITE|DELETE；disp=3 = OPEN_EXISTING
$h=[P.N]::CreateFileW($path,0x00010000,7,[IntPtr]::Zero,3,0x80,[IntPtr]::Zero)
if($h -eq $INVALID){ "被阻止，错误码 " + [System.Runtime.InteropServices.Marshal]::GetLastWin32Error() }
else { [void][P.N]::CloseHandle($h); "可删除" }     # 拿到句柄立刻关，不删
```

- `错误码 32 = ERROR_SHARING_VIOLATION`：有人持有该文件且不允许删除 → **对方一定会失败**。
- `错误码 5 = 拒绝访问`：权限问题，不是占用。
- 这个探针**不修改任何东西**，可以随时对生产文件跑。
- 等价的轻量判据：`os.replace(src, other)` / `rename` 成功与否（同样需要删除权限），
  而且它可以直接写成回归测试。

### A/B 是最快的归因手段

1. 探针测一次（基线）；
2. **停掉可疑进程**，再测一次；
3. 差异就是答案。

再配合两条旁证，几乎不用猜：

- **文件时间戳分布**：同目录里 `map.meta`、`preview.png` 一直在更新，**只有那个 `.s3db`
  停在某个时刻** → 问题精确定位到这一个文件（而不是"整个存档写不进去"）。
- **状态文件会告诉你是谁在读哪一份**：工具自己的 `/health`、选择状态文件、
  对方日志里的路径，都比"我以为它在读 X"可靠。**我这次就是靠 `/health` 显示
  `using=save3` 才发现在读的正是用户正在玩的那份**。

### 报告责任方之前，先问自己三个问题

1. 我的判据针对的是**对方真正要做的那个操作**吗？
2. 我做了 A/B 吗？（停掉我这边，问题还在吗？）
3. 有没有可能**对方自己**就持有这个句柄？（游戏/程序自身持有活库是正常的）

## 三、先怀疑自己的测量，再怀疑代码

**"整齐得可疑的数字"几乎总是测量错误。** 我在一次会话里连续搞错四次，每次都差点当成 bug 报出去：

| 我看到的"bug" | 真相 |
|---|---|
| 每个国家历史**恰好 8 行**（这么整齐很可疑） | 我读了 `d.get("history", d)`，而键名是 `series` → 量到的是**顶层键个数**；真值 19 行 |
| 某字段数量 **= 0** | 我拼错了键名（真实键名很长） |
| 注入体量合计 **0.0 KB** | 辅助函数只接受字符串，我把**数字**传进去，`len("14131")` = 5 |
| 命令退出码 **-1**（像是崩了） | `Select-Object -First N` 截断管道导致；真值 0 |

**复核手段（挑一个，别省）**：

- 换一种独立方式再量一次（另一个接口、另一条命令、另一个文件）；
- 打印**原始结构**（键名清单、类型、长度）而不是只看派生数字；
- 对一个**已知答案**的样本跑同一段代码（对账）。

**PowerShell 特有的三个假失败信号**：

1. `... | Select-Object -First N` → `$LASTEXITCODE` 可能变成非零，**不是命令失败**；
2. 程序往 **stderr** 写东西（比如警告）→ PowerShell 包装成红色 `NativeCommandError`，
   退出码其实是 0；
3. `Get-Content -Raw` 在非 UTF-8 控制台下把 UTF-8 中文显示成乱码（文件本身是好的）。

> 结论：判断成败**看显式打印的退出码**，不要被红字带走。

**查询/字段类的坑（读别人的数据库时高发）**：

- `PRAGMA table_info` + `row_factory=Row` 时，`row[0]` 是**列序号**不是列名（要 `row[1]`）；
- 用错列名（`id` vs `kingdom_id`）→ SQL 合法、**返回空**、不报错；
- 字段名像什么**不代表它是什么**（`enemy` 恒空、`army` 在城市记录里根本不存在）。
  用"交叉求和 / 与对方自带统计对账 / 取值分布是否合理"来验证语义。

## 四、改别人环境的纪律

前提：你可能只有**一次**审批机会，而且要能随时回滚。

1. **先备份**，带时间戳，并把**回滚命令**写进报告：

   ```powershell
   Copy-Item '<backup>\app.js.<stamp>.bak' '<target>\public\app.js' -Force
   ```

2. **锚点断言补丁**：改动写成脚本，每个锚点必须**恰好命中一次**，否则整体中止、不写任何文件
   （绝不能留下"改了一半"的状态）。写后重新读回来自检。

   ```js
   const n = text.split(anchor).length - 1;
   if (n !== 1) { errors.push(`[${label}] 命中 ${n} 次`); return; }   // 全有或全无
   ```

3. **自适应换行与 BOM**：目标文件可能是 CRLF/LF、可能带 BOM。不处理就"锚点匹配不上"，
   而且看起来像"文件被改了"。

4. **一次授权落地**：把多处改动合并进一个脚本一次执行，而不是十次弹窗。
   先 `--dry-run` 验证锚点，再实跑。

5. **语法/自检**：`node --check`、`python -m py_compile`、重新读回目标片段确认插到了正确位置
   （位置错但语法合法是最阴的）。

6. **别把备份放进对方会扫描的目录**；跑完清理临时脚本，或说明为什么留着。

7. **恢复服务**：你为了排查停掉的东西，要重新起来并**验证**；说清哪些是你起的后台任务
   （它们可能随你的会话结束而消失）。

**沙箱要点**：先跑一次看会不会被拒（会得到明确的拒绝标记），
**被拒后用同一条命令申请一次更宽权限**并说明理由——不要一开始就申请最宽的权限，
也不要绕过拒绝去用别的路径实现同一件事。

## 五、报告纪律

- **先取证，再断言。** 顺序永远是：复现 → 定性 → 定位 → 修复 → 验证 → 汇报。
  "我怀疑是 X" 和 "我证明是 X" 要用不同的措辞。
- **区分事实 / 推断 / 置信度**。经验规律要说明它只是经验规律，并给出**可证伪的实验**。
- **主动纠错**：发现自己错了，立刻说出来并说明影响面，不要悄悄改掉。
  （我纠正过："这不是 bug 是我的测量错误"、"这句措辞把服务端默认值说成了用户写的"、
  "元凶是我自己的进程"。）
- **不要用旧读数描述当前状态**：`/health`、进程、文件状态都会变；报告前重新确认一次。
- **如实说明"没做什么"和"没验证什么"**，以及"哪些结论只是推断"。
  一句"409 那条路径我没测，因为要真的跑一轮"比含糊的"都测过了"有价值得多。
- **说清你留下的东西**：起了哪些服务、PID、怎么停；备份在哪、怎么回滚；
  临时文件删了没有。

## 六、开工清单

接到"读某个正在运行的程序的数据 / 在别人机器上排障或改动"时：

- [ ] 先找**对方的日志**和**状态文件**（它们会直接告诉你真相）
- [ ] 只读也要问：我持有句柄会不会妨碍对方写/删？→ 复制副本再读
- [ ] 判断"对方要做的操作"是什么（写？删？替换？），针对它设计判据
- [ ] 用**非破坏性探针**（如申请 DELETE 权限但不删）+ **A/B** 定位责任方
- [ ] 下结论前先复核自己的测量（换一种方式量、打印原始结构、对已知样本对账）
- [ ] 改动前备份 + 锚点断言 + 写后自检 + 语法检查
- [ ] 一次授权落地；被拒就按规则申请一次，不要绕
- [ ] 恢复你停掉的服务并验证；写清 PID 与回滚命令
- [ ] 报告分清事实/推断/未验证；错了立刻说

---

## 七、一句话

**只读也可能弄坏对方——读副本，别持句柄；定位责任方要用"针对对方那个操作"的
非破坏性探针加 A/B；先怀疑自己的测量，再怀疑代码；动别人的东西先备份、可回滚、
一次落地；报告分清事实与推断，错了立刻说。**
