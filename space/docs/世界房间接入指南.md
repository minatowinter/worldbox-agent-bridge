# WorldBox 世界频道接入指南

给 Agent Room 加一个"WorldBox 世界频道"：多个角色各扮演一个国家的领袖，
在同一条时间线里谈判、结盟、宣战、做决策；决策会变成一份**创世者（玩家）
能照着执行的操作清单**，玩家在游戏里做完之后把结果回填，下一轮角色就知道
自己的决策生效了没有。

**已经放进来的东西**：
- `worldbox-bridge.js` —— 世界接入桥（零依赖）
- `server.js` —— 已接入：`world_state` 工具、世界局势注入、动作账本、
  `kind: 'worldbox'` 房间类型、skill 自动复制、世界面板、**多存档选择**、
  **自动生成领袖人设**
- 三套测试：`test/worldbox-bridge.test.js`（10 组）、
  `test/worldbox-integration.test.js`（62 项）、
  `test/worldbox-api.test.js`（33 项，实机）

```powershell
python worldbox_agent.py serve        # 终端 1：世界数据服务（8777）
node server.js                        # 终端 2：房间程序（8787）
node test\worldbox-api.test.js 8787   # 实机验证
```

## 一、先理解三条硬约束

这三条决定了架构，绕不开。**先说清楚，能省掉后面很多返工。**

### 1. 角色不能直接改变游戏，它只能"提案"

真正在游戏里动手的是**创世者**（玩家本人）。角色说"发展农业"，
实际落地是玩家在某座城镇投放食物。

所以必须有闭环：

```
角色提出《国策》 → 平台收集成"待执行清单" → 玩家照着在游戏里做
      ↑                                            ↓
      └────── 下一轮把"已执行/被拒绝"告诉角色 ←──────┘
```

**没有回填，角色会觉得自己在对着空气说话**，几轮之后它就不认真提政策了。

### 2. 世界的节拍是"存档"，不是你的循环

WorldBox 约**每 5 分钟**自动存档一次，外置工具读的就是这个存档。
**你的房间跑得再快，世界也不会变快。**

如果世界没推进你就又开一轮，角色会在**同一帧数据**上反复决策、
反复产出同一份《国策》——这会迅速毁掉对话质量。

所以：**世界指纹变了才开新一轮决策**。指纹由 `worldbox-bridge.js` 提供
（`status().fingerprint` / `hasAdvanced()`）。想让世界走得快，
是**玩家在游戏里手动多存几次档**，不是调你的循环频率。

### 3. 数据有延迟，而且必须如实告诉角色

存档距今通常 0–300 秒，游戏暂停时可能几小时。注入的上下文里**必须带这个数字**，
超过 10 分钟还要带警告。不这样做，角色会把 3 小时前的战报当实时局势来决策，
而它完全没有能力自己发现这一点。

## 二、前置：启动世界数据服务

房间程序是**读**数据的一方；数据由另一个工具提供。两个进程各跑各的：

```powershell
# 终端 1：WorldBox 外置数据服务（默认 127.0.0.1:8777）
cd <worldbox-agent 目录>
python worldbox_agent.py serve

# 终端 2：房间程序（默认 127.0.0.1:8787）
cd C:\Users\24771\Desktop\space
node server.js
```

先确认数据服务是好的：

```powershell
python worldbox_agent.py doctor     # 能不能找到并解析游戏存档
curl http://127.0.0.1:8777/health   # 或者直接浏览器打开
```

要点：

- **数据服务没开时房间不会崩**。桥接模块会降级，注入一段"现在没有世界情报，
  不要编造"的提示，角色照常聊天，只是不做世界决策。
- 游戏**不必**一直开着。关掉游戏后，最后一次存档仍然可读，
  只是数据会越来越旧（会显示过期警告）。
- 换端口：`WORLDBOX_API` 或房间配置里的 `worldbox.baseUrl`。

**位置**：`server.js` 第 459 行，`toolProtocolFor()` 的签名与第 462 行

`toolProtocolFor` 在整个文件里**只被 `buildMessages` 调用了一次**（第 605 行），

```js
function toolProtocolFor(agent) {
```

### 改动 4／4：把世界局势注入系统提示

**位置**：`server.js` 第 605 行，`buildMessages()` 里的 `system` 数组

原来：

```js
    toolProtocolFor(agent),
    '',
    '## 发言准则',
```

改成：

```js
    toolProtocolFor(agent, room),
    '',
    // WorldBox 世界局势（只在 worldbox 房间注入；普通房间返回空串）
    ...(worldbox.bridgeEnabled(room)
```

> 「按需发言」的 YES/NO 判断走的是 `pollDecision`（第 764 行），
> 它自己拼提示、**不经过 `buildMessages`**。所以世界上下文只会注入到
> **真正要说话的那一轮**，不会拖累判断请求——这和最初的估计相比省不少。

```json

  "setting": "这是 WorldBox 世界里各国君主的议政厅。三方正在交战，谁先说话谁就暴露底牌。",
  "mode": "on_demand",
  "rounds": 1,
  "maxTurns": 60,
  "maxToolSteps": 6,
  "followMentions": true,
  "historyLimit": 60,

  "worldbox": {
    "enabled": true,
    "baseUrl": "http://127.0.0.1:8777",
    "strictTick": true,
    "nationOf": {
      "大仁王": "大仁",
      "莱国公": "莱国",
      "元帅": "蜀立后视元帅府"
    }
  },

  "agents": [
    {
      "name": "大仁王",
      "emoji": "👑",
      "model": "deepseek-chat",
      "apiBase": "https://api.deepseek.com/v1",
      "apiKey": "${ENV:DEEPSEEK_API_KEY}",
      "canModifyFiles": true,
      "systemPrompt": "你是大仁王国的国王。谨慎、务实、厌恶无谓的战争。你的父亲（前任国王）死于叛乱。"
    }
  ]
}
```

各字段：

| 字段 | 说明 |
|---|---|
| `enabled` | 是否接入世界数据。缺省 = 不接入（普通房间） |
| `baseUrl` | 世界数据服务地址 |
| `strictTick` | `true` 时注入的提示会额外要求"世界指纹没变就不要重复决策" |
| `nationOf` | **角色名 → 国名** 的映射。角色名必须与 `agents[].name` 完全一致 |

`nationOf` 里的国名要和游戏里一致。如果对不上，桥接模块会在注入的提示里
列出**可用国家名**，让角色自己知道该叫什么。

> **不需要**改前端：`tools`、`worldbox` 这些字段走的是既有的
> `room.worldbox` 属性，`normalizeRoom` 是白名单式构造，未知字段不保留——
> 所以如果你希望网页端也能编辑 `worldbox`，需要顺带在 `normalizeRoom`
> （第 283 行）和 `/api/rooms/update`（第 1041 行）里各加一行。不改的话，
> 直接在 `config.json` 里手写也完全可用。

## 五、角色需要知道的规则（已自动注入）

`worldbox-bridge.js` 会往系统提示里塞这些，你不用自己写：

1. 用 `worldbox-leader-policy` 技能的格式输出《国策》（六节）
2. **你只能提议，不能执行**——要说"请创世者把 X 军移往 (x,y)"，
   不能说"我已派兵"
3. **必须看趋势**——人口从峰值跌了一半，比"人口 1767"重要得多
4. 数据里没有的字段就说没有，**绝不编造数字**
5. 先查距离再决定调兵（每座城都有坐标）
6. 数据超过 10 分钟旧时要说明

这些规则对应两份 skill 文档。**把 skill 也放进房间工作区**，
让角色在需要细节时能读到：

```powershell
cd C:\Users\24771\Desktop\space
xcopy /E /I "<worldbox-agent>\skills\worldbox-leader-policy" "room\worldbox\skills\worldbox-leader-policy"
xcopy /E /I "<worldbox-agent>\skills\worldbox-nation-leader" "room\worldbox\skills\worldbox-nation-leader"
```

> **注意**：房间的文件工具被锁在本房间工作区内（`safePath` 拒绝 `../`），
> 所以角色**读不到** worldbox-agent 目录里的文件。要让它们能读，
> 必须像我上面那样把内容**复制进房间工作区**。
> 同理，`wb.py` 需要 Python 环境且房间没有 shell 工具，
> 所以角色**读数据主要靠注入的上下文 + `world_state` 工具**，而不是跑脚本。

## 六、决策闭环（最关键的一环，别漏）

角色产出的《国策》里带着可执行动作。你需要把它们收集起来交给玩家。

### 6.1 从国策文本里抽取动作

格式已由 skill 固定，用正则抽即可：

```js
// 落点型：执行：请创世者在 北平(4,23) 增建/升级住房，容量 +83
const SITE_RE = /执行[^\n:：]*[:：][^\n]*?([\u4e00-\u9fa5A-Za-z0-9（）()·\-]{1,20}?)\s*[（(]\s*(\d{1,4})\s*[,，]\s*(\d{1,4})\s*[)）]([^\n]*)/;
// 开关型：执行（全国开关）：把「地方高税」下调一档
const SWITCH_RE = /执行\s*[（(]\s*全国开关\s*[)）]\s*[:：]\s*([^\n]+)/;

function parsePolicyActions(text, nation) {
  const out = [];
  for (const line of String(text).split('\n')) {
    const s = line.trim();
    if (!s.includes('执行')) continue;
    let m = SWITCH_RE.exec(s);
    if (m) { out.push({ nation, kind: '开关型', target: null, coord: null, summary: m[1].trim() }); continue; }
    m = SITE_RE.exec(s);
    if (m) { out.push({ nation, kind: '落点型', target: m[1].trim(), coord: [Number(m[2]), Number(m[3])], summary: m[1].trim() + m[4].trim() }); }
  }
  return out;
}
```

**解析失败时不要丢弃原文**——把整份《国策》留给玩家看，
并在下一轮提示角色按格式重写。

### 6.2 动作账本

建议存成 `data/worldbox-actions.json`，结构：

```json
[
  {
    "id": "a1789885000-1",
    "nation": "大仁",
    "kind": "落点型",
    "target": "北平",
    "coord": [4, 23],
    "summary": "北平增建/升级住房，容量 +83",
    "status": "proposed",
    "fingerprint": "…\\map.wbax|1789872887",
    "createdAt": 1789885000000,
    "decidedAt": null,
    "note": ""
  }
]
```

`status` 取 `proposed`（待玩家执行）→ `executed` / `rejected` / `obsolete`。

### 6.3 世界推进后作废旧提案

```js
// 世界指纹变了 → 上一帧还没裁决的提案，针对的局势已经过去了
for (const a of actions) {
  if (a.status === 'proposed' && a.fingerprint !== status.fingerprint) {
    a.status = 'obsolete';
    a.note = '世界已推进，该提案针对的局势已过去';
  }
}
```

不做这一步的话：世界从 212 年走到 213 年，上一帧"给北平增建住房"还挂在
待执行清单上，而北平的无家可归可能已经变了——角色会看到自己针对旧局势的
提案"没人理"，产生错误认知。

### 6.4 把执行结果回填给角色

下一轮注入上下文时，把最近已裁决的动作一并给出。桥接模块的做法是
在系统提示里附上，你也可以直接作为一条系统消息推进房间时间线：

```js
pushSystem(room, `【创世者裁决】你上一轮提出的政策：
- 在 北平(4,23) 增建住房 → 已执行（已增建 90 人份）
- 把「地方高税」下调一档 → 被拒绝（今年不改税率）`);
```

`pushSystem` 是 server.js 已有的函数（第 651 行附近），角色看得到。

## 七、把决策挂到"世界推进"上（可选但强烈建议）

默认情况下，房间的 `runLoop` 是按发言模式跑的。WorldBox 房间建议改成
**世界推进才开一轮**，否则角色会在同一帧上重复决策。

最小做法：在 `runLoop`（第 812 行）开头发起一轮之前加一个守卫——

```js
// 只在 WorldBox 房间、且开了 strictTick 时生效
if (room.worldbox?.enabled && room.worldbox.strictTick) {
  const bridge = worldbox.getBridge(room);
  const now = await bridge.status();
  const sameWorld = now && room.worldbox.lastFingerprint === now.fingerprint;
  if (sameWorld && !forceWorldTick) {
    pushSystem(room, '（世界尚未推进——局势没有变化。可以继续谈判与表态，但先不要产出新的《国策》。）');
    return;                       // 不排队发言
  }
  if (now) room.worldbox.lastFingerprint = now.fingerprint;
}
```

（`forceWorldTick` 是你的手动放行开关，比如玩家点"强制推进一轮"。）

| **世界事件** | `world_state` / `/api/v1/world` 的全局事件 | 系统消息（灰色）：「212 年，大仁攻占琼州」 |
| **领袖《国策》** | 角色发言 | 带动像 / 国名 / 性格标签 |

| **待执行清单** | 动作账本里 `status === 'proposed'` | 固定侧栏，玩家照着在游戏里做 |

### 顶部显示世界状态

`bridge.statusLine()` 直接返回一行可显示的文本：


```
🌍 Skulls of Misery 第 212 年 · 存活 3/3 国  ⚠️ 数据已 268.0 分钟旧，可能已过期
```

**这个横幅很重要**——它是玩家判断"现在看到的局势还算不算数"的唯一依据。

## 九、角色的人格与"内心"

Agent Room 的**「内心」日志**和 WorldBox 的领袖扮演是天然一对：

- 角色的思考过程、工具调用、发言判断理由 → 房间的"内心"（已实现）
- 《国策》的「**四、内心**」一节 → 领袖真实的想法，也进内心

`worldbox-leader-policy` 还要求每个领袖维护两个文件：

```
room/<房间目录>/persona.md              人格设定（价值观/恐惧/渴望/矛盾/说话方式）
room/<房间目录>/memory.md               按年追加的记忆
```

因为**角色的文件工具能读写本房间工作区**，这两个文件正好落在它能碰到的范围内。
建议在房间设定里明确要求：

> 每轮动笔前先 `read_file` 你的 `memory.md`；决策后把这一年的经过
> `append_file` 到 `memory.md`。一个不记得自己承诺过的领袖，不配称为一个角色。

这是让**同一个角色跨回合还是同一个人**的关键。没有它，每隔几轮角色就会
"失忆"，人格立不起来。

## 十、成本与性能

实测（3 个国家的世界）：

| 项目 | 体积 |
|---|---|
| 注入的世界局势段落 | **约 6.8 KB** |
| 其中：角色国情上下文 | 约 5.5 KB |
| `world_state` 工具返回 | 约 5.6 KB |

按 5 分钟一轮、5 个角色算：每轮约 34 KB，一天 288 轮 ≈ 10 MB。
**完全可控**，前提是别把 27 KB 的完整国情直接灌进去——
桥接模块已经帮你压到 5.5 KB（只保留最要紧的 8 座城 + 完整趋势）。

桥接模块有 8 秒缓存，房间里 N 个角色拉同一份数据不会打 N 次请求
（实测连续 20 次 `status()` 耗时 0 ms）。

**"按需发言"模式的实际开销比看上去小**：它的 YES/NO 判断走 `pollDecision`，
不经过 `buildMessages`，所以**只有真正发言的那一轮才注入世界局势**。
5 个角色一轮里可能只有 2 个发言 → 注入 2 次而不是 5 次。

## 十一、排错

| 症状 | 原因 | 处理 |
|---|---|---|
| 角色说"没有世界情报" | 数据服务没开 | 跑 `python worldbox_agent.py serve` |
| 状态行显示"世界服务不可用" | 端口不对 / 服务崩了 | 浏览器打开 `http://127.0.0.1:8777/health` |
| 角色找不到自己的国家 | `nationOf` 里的国名和游戏里不一致 | 看注入提示里的「可用国家」列表，或跑 `wb.py whoami` |
| 数据显示几小时前 | 游戏关了或暂停了 | 在游戏里手动按一次保存，10 秒内会刷新 |
| 角色反复产出同一份国策 | 没挂世界节拍 | 开 `strictTick` + 第七节的守卫 |
| 角色说"我已派兵" | 提示没说清权限 | 改动 4 已经注入"你只能提议"；再确认 skill 在工作区里 |
| 中文乱码 | 控制台编码 | 跑数据服务前设 `$env:PYTHONIOENCODING='utf-8'`；浏览器端不会有这个问题 |
| 网页端看不到 `worldbox` 配置 | `normalizeRoom` 是白名单 | 见第四节末尾的说明 |

**先用自检脚本定位**：


它会逐项告诉你：世界状态能不能读到、节拍器对不对、国家名能不能解析、
上下文多大、降级是否正常、缓存是否生效。**十项全过，说明桥接层没问题**，

## 十三、多存档选择（重要）

一个正常玩家会有**几十个存档**，分属不同世界、不同时间。本机实测：

| 序号 | 世界 | 时间 | 备注 |
|---|---|---|---|
| #1 | Skulls of Misery | 3 分钟前 | 当前在玩 |
| #6 | Skulls of Misery | 64 分钟前 | 手动存档 |
| #7 | **Isles of Despair** | **38 天前** | 完全不同的世界，20 个国家 |
| #12 | Sanctum and Chaos | 55 天前 | |
| #31 | Generated | 1411 天前 | 老存档 |

**如果永远只取"最新"，房间就会被接到一个你根本不关心的世界上**——
或者接到一个几小时前的旧世界却不自知。所以显式选择是必需的。

### 13.1 数据工具侧

```powershell
python worldbox_agent.py saves                 # 列出所有存档（世界名/时间/新鲜度）
python worldbox_agent.py select "#7"           # 锁定第 7 份
python worldbox_agent.py select 1786604527     # 按文件夹名
python worldbox_agent.py select "Isles"        # 按世界名
python worldbox_agent.py select latest         # 恢复"跟随最新"
python worldbox_agent.py export --save "#3"    # 单次导出指定存档，不改全局选择
```

选择记在 `data/worldbox_selection.json`，下次启动自动沿用。
（游戏数据目录不可写时会自动退到工具的 `data/` 目录，并如实告知，不静默失败。）

服务端接口：

| 接口 | 说明 |
|---|---|
| `GET /api/v1/saves` | 列出所有存档（只读 `map.meta`，**不解析大文件**，31 份约 18ms） |
| `GET /api/v1/saves/select?key=<key\|#序号\|世界名\|latest>` | 切换并记住 |

`/health` 会回显 `save_selection: { requested, using, mode, matches }`。
**选择没匹配上时 `matches: false`，不会悄悄用别的存档。**

### 13.2 房间程序侧

```http
GET  /api/worldbox/saves
  -> { ok, dataDir, count, selection, locked, saves: [{key, world, time, age, selected}] }

POST /api/worldbox/save   { "key": "#7" }     也接受 "latest" 恢复跟随最新
```

切换后会自动做三件事，因为**换了世界，很多东西就不成立了**：

1. **清空动作账本** —— 旧提案针对的局势已不存在；
2. **按新世界重建领袖** —— 国名、国王、国家数都可能完全不同；
3. **重算所有领袖的人设** —— 旧人设里的国名可能已不存在。

`room.worldbox.saveKey` 会写进 `config.json`，重启不丢。

> ⚠️ 房间**正在运行**时不允许切换（返回 409），
> 否则会出现"一半角色还在旧世界"的错乱。先停止再切。

> 💡 **性能细节**：`/api/state` **不**携带整份存档列表（那个端点每次发言/轮询
> 都会被拉），只带 `savesCount`；完整列表走 `/api/worldbox/saves`。

## 十四、自动生成领袖人设

新建 WorldBox 房间时，领袖只有一句"你是 X 国的领袖"，缺客观国情。
而正确的人设其实**完全由数据决定**：国王与其特质、国家特质、国力地位、
人口与军队趋势。让使用者手抄一遍既枯燥又容易抄错，所以自动生成。

**真实输出样例**：

```
你是 WorldBox 世界「Skulls of Misery」中「大仁」的国王，你的名字是「Morel Huifang」。
世界当前是第 194 年，你的国家有 2665 人口、478 军队、20 座城市、
领土地块 1000，声望 702（第 1 名）。
你的性格倾向是：坚韧、睿智、金牙。
你的国家正在恢复（近年人口变化 +608），你倾向于稳步扩张。
你的军队在缩水，你不愿轻易开启新的战争。
你目前正在打 1 场战争：对莱国。
你周边的国家：莱国（军队 5，人口 63，与你是敌对）……
你是一个真实历史里的君主，不是助手。你有自己的野心、恐惧和执念。
做任何决策前先看平台给你的世界局势数据，尤其是**趋势**——单看当前一帧说明不了问题。
你只能提出政策，实际执行者是创世者（玩家）。
数据里没有的东西就说没有，绝不编造数字。
```

### 14.1 四条设计约束

| 约束 | 为什么 |
|---|---|
| **绝不覆盖手写的 `systemPrompt`** | 那是使用者对角色的设定，优先级最高 |
| **存进独立字段 `systemPromptAuto`** | 一眼看出哪段是系统补的；清空即可重新生成 |
| **只在空白或世界已变时生成** | 否则每轮重写，把上下文搅乱 |
| **记录生成时的存档指纹**（`systemPromptAutoFor`） | 换存档/世界推进后必须重算，旧国名可能不存在了 |

最终人设 = `手写 + 自动生成`（`worldbox.rolePromptFor(agent)`）。
`publicAgent()` 额外给出 `effectivePrompt` 供界面预览。

### 14.2 触发时机

- 建 WorldBox 房间时自动生成一次
- 切换存档后自动重算
- 手动：`POST /api/worldbox/prompts { "force": true }`

`force: true` 会连手写的也重算——**但只重算自动部分，手写的仍然不动**。

> **注意**：角色名必须能映射到国家（`worldbox.nationOf` 或 `agent.worldboxNation`），
> 否则会被跳过，并在返回的 `details` 里说明原因（例如"未指定国家"）。
