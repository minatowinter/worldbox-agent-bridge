# Agent Room · 多 Agent / 多房间协作环境

让**多个不同角色的大模型 Agent**通过 API 接入同一个房间：它们共享一份对话历史、共享一个工作区目录，
可以互相 `@` 点名、接力干活，并且**真的会动手写文件**——或者只被允许动嘴。

网页端实时展示全过程。

房间分两种**模式**：

| 房间模式 | 说明 |
| --- | --- |
| 💬 **普通房间** | 自由设定场景与角色，没有外部世界数据。讨论、评审、角色扮演都行。 |
| 🌍 **WorldBox 世界频道** | 接入《世界盒子》(WorldBox) 的游戏存档。角色扮演真实存在的国家领袖，读**真实情报**、产出《国策》，由你（创世者）在游戏里执行后回填。 |

```
┌────────────┐  SSE 实时推送   ┌────────────────────────────────────┐
│  浏览器 UI │ ◀───────────── │  server.js（零依赖 Node）           │
└────────────┘ ─────────────▶ │  多房间 / 调度器 / 工具执行 / 内心   │
                              └──┬──────────┬───────────┬──────────┘
                                 │          │           │
                    OpenAI 兼容 API   room/<房间>/    worldbox-bridge.js
                   (DeepSeek/本地)    独立工作区     ↕ 127.0.0.1:8777
                                                    WorldBox 存档数据服务
```

## 快速开始

需要 **Node.js 18+**（零第三方依赖，不用 `npm install`）。

```bash
node server.js
# 打开 http://127.0.0.1:8787
```

Windows 下双击 `start.bat` 也一样。

首次启动会生成 `data/config.json`，并预置一个房间和三个角色（小周 / 老陈 / May）。

### 填 API Key

三种方式任选：

1. **网页里填**：点某个角色的「编辑」→ 填 **API Key** → 保存 → 点「🔌 测试连接」验证。
2. **改配置文件**：`data/config.json` 里每个 agent 的 `apiKey`（明文保存，注意保密）。
3. **用环境变量**（推荐，key 不落盘）：`apiKey` 填 `${ENV:DEEPSEEK_API_KEY}`，再设置环境变量。

```powershell
$env:DEEPSEEK_API_KEY="sk-xxxx"; node server.js
```

任何 **OpenAI 兼容** 服务都能用（OpenAI / Kimi / 通义 / 智谱 / 本地 Ollama、vLLM、LM Studio…），
只要改 `apiBase` + `model`。你可以让同一个房间里的角色用**不同的模型**。

## 🌍 WorldBox 世界频道

详细设计见 `docs/世界房间接入指南.md`，这里只讲怎么用。

### 前置：启动世界数据服务

房间程序是**读**数据的一方，数据由外置工具提供，两个进程各跑各的：

```powershell
# 终端 1：WorldBox 外置数据服务（默认 127.0.0.1:8777）
cd <worldbox-agent 目录>
python worldbox_agent.py serve

# 终端 2：房间程序
cd C:\Users\24771\Desktop\space
node server.js
```

确认数据服务正常：浏览器打开 `http://127.0.0.1:8777/health`，或跑 `python worldbox_agent.py doctor`。

> 数据服务没开时房间**不会崩**：桥接模块会降级注入"现在没有世界情报，不要编造"的提示，
> 角色照常聊天，只是不做世界决策。游戏也不必一直开着，最后一次存档仍然可读。

### 建一个世界房间

点顶部 `＋` → 选 **🌍 WorldBox 世界频道** → 创建。系统会自动：

1. 读取世界数据，**按世界里真实存在的国家各建一个领袖角色**（名字就是国名）；
2. 建立 角色 → 国家 的映射（`nationOf`），所以每个领袖只看得见自己那份国情；
3. 把 `skills/` 复制进该房间工作区（`room/<房间>/skills/…`），让领袖能读到扮演规范；
4. 记下当前世界指纹，作为世界节拍的基准。

连不上数据服务也照样建房间，只是先放 3 个占位领袖，之后在「房间设置 → 国家分配」里补。

### 闭环：提案 → 执行 → 回填

这是整个功能的核心。**角色不能直接改变游戏**——真正动手的是你（创世者）。

```
领袖读真实情报 → 产出《国策》 → 平台抽出可执行动作 → 待执行清单
     ↑                                                    ↓
     └──── 下一轮把"已执行 / 被拒绝"回填给它 ←── 你在游戏里做完后裁决 ──┘
```

1. **提案**：领袖发言时按 skill 格式写出可执行动作，平台用正则自动抽取：
   - 落点型：`执行：请创世者在 北平(4,23) 增建/升级住房，容量 +83`
   - 开关型：`执行（全国开关）：把「地方高税」下调一档`
   解析失败的整份《国策》**不会丢弃**，会以「待解析」条目留在清单里供你查看。
2. **待执行清单**：右侧面板「📜 待执行」标签页，可以「📋 复制清单」直接照着在游戏里做。
3. **裁决**：做完点 `✅ 已执行` 或 `❌ 被拒绝`（可填说明）。这会立刻在房间里生成一条
   `【创世者裁决】…` 系统消息，并注入到所有领袖下一轮的上下文里。

### 决策额度：一次决策是有限的

领袖很容易一轮就开出十几条政策（"修路、扩军、开矿、减税、宣战……"），
结果既做不完、也让游戏失去张力。所以世界房间对**每轮提案数量**做了硬限制：

- **默认每个领袖每轮最多提出 3 条**可执行动作，超出的由服务端**直接丢弃**，
  房间里会出现一条系统提示，该角色的「内心」里也会写明"解析出 N 条，入账 3 条，丢弃 N-3 条"。
- 同时要求决策**轻度、小步、可逆**：一条只解决当下最紧的一件事，不许一轮改造整个国家。
- 额度**只限制"要创世者动手"的动作**。说话、谈判、结盟、放狠话不消耗额度——
  所以一个领袖完全可以这轮只发言、不提任何政策。
- 提示里还会告诉它"你当前还有 N 条提案在等裁决"，避免反复提交同一件事。

额度可以在「房间设置 → 每轮最多提案」里改（1–9），右侧「📜 待执行」面板顶部会显示当前额度。
想彻底放开，把它调到 9。

### 世界节拍：不要在同一帧上重复决策

WorldBox 约每 5 分钟自动存档一次，**房间跑得再快世界也不会变快**。
如果世界没推进你就又开一轮，角色会在同一帧数据上反复产出同一份《国策》，很快就把对话质量毁掉。

所以世界房间默认开启 **世界节拍**（`strictTick`）：

- 每次开新一轮前先比对世界指纹（`存档路径|时间戳`）；
- 指纹没变 → 不开新一轮，只往房间推一条提示："世界尚未推进，可以先谈判表态，但先不要产出新国策"；
- 指纹变了 → 上一帧还没裁决的提案自动标记为**已过期**（它针对的局势已经过去了），并提示领袖。

想立刻跑一轮，点横幅上的 **⏩ 强制开一轮**；想关掉节拍，取消勾选「世界没推进就不决策」。
在游戏里手动多存几次档，世界就会走得快一些——这才是正确的加速方式。

### 世界状态横幅

顶部横幅是判断"现在看到的局势还算不算数"的唯一依据：

```
🌍 Skulls of Misery 第 212 年 · 存活 3/3 国  数据 2.5 分钟前
🌍 Skulls of Misery 第 212 年 · 存活 3/3 国  ⚠️ 数据已 281.5 分钟旧，可能已过期
```

数据超过 10 分钟会变黄告警，服务不可用会变红。

### 世界房间里的角色会多出什么

- **多一个只读工具 `world_state`**（只读角色也能用）：按需拉取本国完整国情、城市坐标、逐年趋势、
  列国军力对比、战争与外交状态。做任何决策前都该先查它。
- **系统提示里自动注入**当前世界快照 + 该国情报（约 6.8 KB），并附带扮演规则：
  只能提议不能执行、必须看趋势而不是单点、先查距离再调兵、数据没有的字段绝不编造。
- **`memory.md` / `persona.md`**：领袖被要求每轮动笔前先 `read_file memory.md`，
  决策后把这一年 `append_file` 进去——这是让同一个角色跨回合还是"同一个人"的关键。

普通房间**完全不受影响**：角色看不到 `world_state`，系统提示里也不会出现任何世界内容
（`node test/worldbox-integration.test.js` 里专门有一组断言在守这件事）。

### 世界房间相关自检

```powershell
node test/worldbox-bridge.test.js        # 桥接层自检（读数据/节拍/降级/缓存）
node test/worldbox-integration.test.js   # 端到端：注入隔离 → 工具 → 抽动作 → 裁决 → 回填
```

## 六个核心能力

### 1. 多个房间，互相独立

顶部下拉框切换房间，`＋` 新建，`✎` 改名，`🗑` 删除。

每个房间**完全独立**：

| 独立内容 | 说明 |
| --- | --- |
| 房间设定 | 这个房间是什么场景、谁和谁是什么关系 |
| 角色名单 | 各房间可以有完全不同的角色阵容 |
| 对话记录 / 内心日志 | 互不可见 |
| 工作区目录 | `room/room1/`、`room/room2/` … 互不干扰 |
| 模式 / 轮数 / 各种参数 | 每个房间单独设置 |

> 删除房间时会保留它的工作区文件夹（`room/roomN/`），只清除配置与对话记录。

### 2. 角色可以被设为「只读」

编辑角色 → **文件权限** 选择：

- `可读写工作区`：能用 `write_file` / `append_file` / `delete_file`；
- `只读（仅对话）`：只能 `list_files` / `read_file`，写操作会被服务端**硬拒绝**，
  连工具说明里都不会出现写工具，System Prompt 里会明确告诉它"你是只读的"。

适合扮演"用户""评论家""只负责提问的人"这类不该动手改文件的角色。角色卡片上会显示 `🔒 只读`。

### 3. 三种发言模式

| 模式 | 行为 |
| --- | --- |
| **轮流发言** | 每一轮让所有启用角色各说一次。适合头脑风暴、轮流表态。 |
| **按需发言** | 每次有人说完，其余角色**各自判断"我要不要开口"**，只有判断为需要的角色才会发言；连续两轮无人想说话就自动收场。 |
| **手动点名** | 不自动排队，你点某个角色的「发言」按钮它才说话。 |

`按需发言` 的底层逻辑：每次发言后，服务端会**并行**向其余每个角色发一次轻量判断请求
（"基于刚才的对话，你现在需要发言吗？只输出一行 YES/NO + 20 字理由"），
回答 YES 的角色进入发言队列，回答 NO 的跳过，判断理由会记进它的「内心」。
代价是会产生额外的判断调用（N 个角色 ≈ 每次多 N-1 次请求），好处是角色不会为了说话而说话。

三种模式下 `@名字` 都有效：被点名的角色会被直接插队发言。

### 4. 角色有「内心」

每个角色分成两条流：

- **房间时间线**：只有角色的正式发言（和你、系统消息）。干净、可读，就是一场对话。
- **内心日志**（点角色卡片的「内心」按钮，或点发言右下角的 `💭 内心`）：
  思考过程、每一次工具调用的参数与结果、按需发言时的判断理由、错误堆栈。

也就是说，Agent 在后台查文件、写文件、被拒绝、反复修改的全过程都留在它自己的内心里，
房间里只呈现它最终说出口的那句话。

### 5. 房间设定（而不是"团队目标"）

房间里的角色不一定是一个团队——他们可能是谈判对手、家人、历史人物、采访者与受访者。
所以共同背景叫**房间设定**，用来描述场景、角色关系和当前情境，会作为共同背景发给每个角色。

```
这是一场产品评审会。小周是产品经理，负责推进需求；老陈是工程师，负责实现对不合理的需求说不；
May 代表真实用户，负责挑毛病。三个人要围绕"下一版做什么"聊出一个可执行的结论。
```

### 6. 整齐的工作区结构

```
room/                  工作区根目录
  room1/               房间 1 的工作区
    notes/
    src/
  room2/               房间 2 的工作区
```

每个房间只能访问自己那一份，路径越界（`../`）会被拒绝。网页右侧面板顶部会显示当前房间的路径。
旧版本的 `shared/` 会在首次启动时自动迁移进第一个房间并清理掉。

## 角色能用的工具

角色在回复里写这样的块，服务端会真正执行，把结果回喂给它，然后它继续下一步
（默认最多 4 步，可在房间设置里改）：

```xml
<tool name="write_file">
{"path": "src/hello.py", "content": "print('hi')"}
</tool>
```

| 工具 | 作用 | 只读角色 |
| --- | --- | --- |
| `list_files` | 列出本房间工作区文件 | ✅ |
| `read_file` | 读取文件 | ✅ |
| `write_file` | 写入 / 覆盖（自动建目录） | ❌ 被拒绝 |
| `append_file` | 追加内容 | ❌ 被拒绝 |
| `delete_file` | 删除文件 | ❌ 被拒绝 |
| `world_state` | 拉取 WorldBox 世界情报（**仅世界房间**） | ✅ |

限制：路径被锁定在本房间工作区内；单个文件上限 256 KB。

## 常见问题

**列表里提示「未配置 Key」** — 该角色没有 API Key。点「编辑」补上，或用 `${ENV:XXX}`。

**连续 3 次调用失败会自动停止** — 防呆机制，避免 key 错误时把配额刷爆。

**按需发言一直没人说话** — 连续两轮全员 NO 就会自动收场并提示"讨论告一段落"，
这是正常的收敛，不是卡住。想让它继续聊，你在房间里说一句话即可。

**角色一直只聊天不写文件** — 在它的人设里明确要求"必须调用 write_file 产出真实文件"，
并把「每个角色最多工具步数」调大；或者检查它是不是被设成了只读。

**世界房间点「▶ 开始」没反应** — 世界指纹没变，被节拍挡住了。这是设计如此，
点「⏩ 强制开一轮」或在游戏里手动存一次档。

**领袖说"没有世界情报"** — 数据服务没开，跑 `python worldbox_agent.py serve`。

**领袖找不到自己的国家** — 房间设置里的「国家分配」和游戏里的国名对不上。
打开房间设置，从下拉框里选正确国家（下拉项来自实时世界数据）。

**领袖反复产出同一份国策** — 检查「世界没推进就不决策」是否被关掉了。

**领袖说"我已派兵"** — 提示里已经写明"你只能提议"，若仍如此，把它的人设再强调一遍，
并确认 `skills/` 已复制进该房间工作区。

**中文乱码** — 跑数据服务前设 `$env:PYTHONIOENCODING='utf-8'`；浏览器端不受影响。

**想换端口** — `set PORT=9000 && node server.js`。

**彻底重置** — 停掉服务，删除 `data/` 和 `room/`，重新启动即可恢复默认。
